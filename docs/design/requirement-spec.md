# 销售订单托盘摆放 · 需求规格说明

> 依据：生产代码（mes_brake 前端 `SaleOrderPalletContent.vue`、`PackagePalletPreview`；mes_brake_pads_backend 后端
> `SaleOrderPalletPlanServiceImpl`、`PalletPackingAssembler`、`PalletPackingEngine`、托盘相关实体与 Mapper），
> 2026-07-10 ~ 09-02 托盘相关提交，以及 2026-08-07 业务需求变更清单。本仓库为演示工程，接口路径与生产一致。

## 1 范围

| 项 | 内容 |
|---|---|
| 所属流程 | 销售订单：销售 → 技术 → 采购（盒子匹配 / 托盘摆放 / 费用计算）→ 运费 → 财务 → 领导 |
| 本功能 | 采购节点的「托盘摆放」：按批次把订单产品装到托盘上，给出托数、每托构成、利用率和三维预览 |
| 不在范围 | 运费、包装费用、财务价格计算；托盘标准基础资料的维护页面 |

## 2 角色与入口

| 角色 | 操作 |
|---|---|
| 销售 | 录单时选择托盘标准（托盘类型），作为采购计算的默认值 |
| 采购 | 在「托盘摆放」页签调整参数、计算、保存草稿、提交 |
| 下游节点 / 查看人 | 只读查看已保存的托盘结果和三维预览 |

## 3 输入

| 编号 | 输入 | 来源 | 规则 |
|---|---|---|---|
| IN-01 | 托盘标准 | `mes_pallet_standard`（只取 ENABLED='1'、DELETED=0） | 必选；长宽规格覆盖欧标、美标、国标 |
| IN-02 | 货物重量限制（kg） | 页面输入 | 必须为大于 0 的有限数 |
| IN-03 | 货物高度限制（mm） | 页面输入 | 必须为大于 0 的有限数；需求清单要求默认高度 1150 |
| IN-04 | 允许混托 | 开关，默认开 | 关闭时不同产品不能同托 |
| IN-05 | 允许盒箱混托 | 开关，默认关 | 仅在允许混托时生效 |
| IN-06 | 允许无盒混托 | 开关，默认关 | 仅在允许混托时生效 |
| IN-07 | 销售批次 | 订单批次 | 每个批次单独计算、单独保存；空串表示未分批 |
| IN-08 | 订单产品 | 订单产品 + 技术/包装快照 | 数量、客户号、单重、包装外尺寸、每盒件数、每箱盒数 |

## 4 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 包装模式：有每箱盒数 → carton 纸箱；否则有每盒件数 → box 盒装；都没有 → virtual 无盒（按大外圆和总高生成虚拟包装）。订单内出现多种模式时方案记为 mixed |
| BR-02 | 包装容量：box = 每盒件数；carton = 每盒件数 × 每箱盒数；virtual = 1 |
| BR-03 | 先按产品（产品键 + 订单产品 + 包装模式）分组装整托，再把未装满的尾托作为候选 |
| BR-04 | 允许混托时合并尾托；盒箱混托、无盒混托关闭时，尾托先按包装规则分区再合并 |
| BR-05 | 单箱重量超过限重、单箱高度超过限高时直接报错，并指出是哪一行 |
| BR-06 | 稳定性：上层每个箱子的底面必须 100% 落在下层箱子顶面上；混托时不同产品在水平投影上不能交叠 |
| BR-07 | 托盘结果按 single / mixed 分组，给出每托层数、箱数、重量、高度、面积利用率、高度利用率、稳定性评分 |
| BR-08 | 稳定性评分 = 面积利用率×70 + min(层数×5, 15) − max(0, 高度利用率−0.85)×40，限定在 0~100 |
| BR-09 | 计算即保存：输入指纹与已存 `CALCULATION_INPUT_HASH` 相同时直接复用，不重复计算 |
| BR-10 | 保存时按 (订单, 批次) 加锁，先删除旧方案、分组、明细，再写入新结果 |
| BR-11 | 保存草稿/提交前校验：托盘标准、混托三开关、限重、限高与已计算方案一致，否则提示“××已变更，请重新计算后再保存” |
| BR-12 | 上游节点（销售、技术）修改并重新提交后，托盘结果随包装、运费、财务结果一起失效 |

## 5 输出

| 编号 | 输出 | 存储 |
|---|---|---|
| OUT-01 | 方案汇总：托盘总数、箱数、货物总重、平均利用率、是否有混托 | `mes_sale_order_pallet_plan` |
| OUT-02 | 分组：分组号、类型、产品键、托数、箱数、重量、利用率 | `mes_sale_order_pallet_group` |
| OUT-03 | 每托明细：托盘号、产品构成、层数、箱数、重量、高度、利用率、稳定性评分 | `mes_sale_order_pallet_item` |
| OUT-04 | 箱子三维布局：位置、占用尺寸、旋转、层号、支撑来源 | `BOX_LAYOUT` JSON |
| OUT-05 | 三维预览：托盘底座 + 盒/箱/无盒刹车盘模型，可旋转缩放 | 前端 `PackagePalletPreview` |

## 6 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/pallet-standard/listEnabled` | 启用的托盘标准 |
| GET | `/sale-order/pallet/{id}?batchId=&refresh=` | 托盘页数据（装配结果 + 已存方案） |
| POST | `/sale-order/pallet/{id}/calculate?batchId=` | 计算并保存 |
| PUT | `/sale-order/pallet/{id}/draft?batchId=` | 保存草稿 |
| PUT | `/sale-order/pallet/{id}/next?batchId=` | 提交（进入下一节点） |
| GET | `/sale-order/pallet/{id}/view?batchId=` | 只读查看 |
| GET | `/sale-order/pallet/{id}/preview?batchId=&palletNo=` | 单托三维布局 |

演示仓库实现了除 `next` 以外的同名接口。

## 7 异常与提示

| 场景 | 提示 |
|---|---|
| 限重或限高为空、≤0 | 货物重量限制必须大于0 / 货物高度限制必须大于0 |
| 未选托盘标准 / 标准不存在 | 托盘标准不能为空 / 所选托盘标准不存在 |
| 产品行缺数据 | 产品数量必须大于0、未维护客户号对应关系、缺少单重、未匹配包装盒外尺寸 / 未匹配纸箱外尺寸 / 缺少大外圆或总高、每盒件数必须为正整数、每箱盒数必须为正整数 |
| 单箱超限 | ××单箱产品重量(…kg)超过货物重量限制(…kg)；××单箱货物高度(…mm)超过货物高度限制(…mm) |
| 并发保存 | 当前订单托盘结果正在保存，请稍后再试 |
| 参数在计算后被改 | 托盘标准 / 混托 / 盒箱混托 / 无盒混托 / 货物重量限制 / 货物高度限制已变更，请重新计算后再保存 |

## 8 验收标准

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-01 | 单产品 12 箱，箱 400×300×200、8kg，托盘 1200×800，限重 500、限高 1200 | 计算 | 1 托，2 层，96kg，面积利用率 0.75 |
| AC-02 | 两种产品各有尾托，允许混托 | 计算 | 尾托合并，分组类型出现 mixed，且合并后每个上层箱底面 100% 受支撑 |
| AC-03 | 同上，关闭混托 | 计算 | 不同产品不同托，全部为 single |
| AC-04 | 有一箱重量超过限重 | 计算 | 报错并指出该行，不保存 |
| AC-05 | 输入未变 | 再次计算 | 不重新计算，直接返回已存方案 |
| AC-06 | 计算后修改了限高 | 保存草稿 | 提示“货物高度限制已变更，请重新计算后再保存” |
